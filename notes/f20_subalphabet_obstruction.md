# F20 部分アルファベット: 5.5 の機構は「同じ ε の 2 文字の順序」で破れる（2026-07-25、負の結果）

**台帳行**: `F20-SUB10-OBS-01`。導出はこの note にある（2026-07-26 に `RESULTS.md` の要約節をここへ統合したので、id で引くとここに来る）。

`F20-FULL-OBS-01`（§5.12）は全 20 元での失敗を **ε = 2 の 5 文字**に局在させ、次の一手として
「(ii) certification が通る 15 文字部分アルファベット `ε ∈ {0,1,3}` を先に完成させる」を推奨した。
**この推奨は誤りだった。** 15 文字どころか **10 文字 `ε ∈ {0,1}`** で既に機構が破れ、
しかも理由は ε = 2 とは無関係である。

機械検証: `scripts/research/f20_subalphabet_obstruction.py`（約 12 秒、厳密判定）。
実行マニフェスト: `data/experiments/f20_subalphabet_obstruction.md`。
台帳: `F20-SUB10-OBS-01`。

## 1. certify されるパターンの実表

`f20_full_alphabet.py` の `candidate_patterns()` は `h == g`（同一文字ペア）を除外している
（A4 スクリプト由来。あちらでは純粋冪が落ちると分かっていたため）。ここでは同一文字ペアも
含めて全署名を厳密判定した。したがって下表は各アルファベットの**完全な** certified family である。

| アルファベット | base | single (ε=0) | pair の certify されるもの |
|---|---|---|---|
| `ε ∈ {0,1}`（10 文字） | CERT (monoid 16) | CERT (17) | **なし**（(0,1) と (1,1) は period 2、同一文字 (1,1) は period 4） |
| `ε ∈ {0,1,3}`（15 文字） | CERT (46) | CERT (47) | (1,3) と (3,1) のみ、計 50 個 (monoid 82) |
| 全 20 元 | **FAIL** (62, period 2) | — | なし（base が既に落ちる、§5.12） |

**10 文字ではペア情報が一つも取れない。** これが以下の障害の直接の原因である。

### 誤った一般化を撤回する

一度は「Σε ≡ 0 (mod 4) ⟺ certifiable」という法則を立てたが、**これは成り立たない**。
合成実験（phase 群を `Z/m`、ε 多重集合を可変にしてトークン DFA の transition monoid を直接列挙）では

- `Z/3`: base は CERT、ペア 13/16 が certify（Σε ≠ 0 でも certify されるものが多数）
- `Z/5`: base は CERT、ペア 31/36 が certify（同様）
- `Z/4`（ε = 2 を含む）: base が落ちるので 0/25

となり、Σε ≡ 0 は必要でも十分でもない。上表の 15 文字での一致（8 署名すべてで
Σε ≡ 0 ⟺ certifiable）は **ε 多重集合 {0,1,3} という特定の設定での事実**であって法則ではない。
本ノートは上表の実測のみに依拠する。

## 2. 障害（`F20-SUB10-OBS-01`）

`Σ₁₀ = { g ∈ F20 : ε_g ∈ {0,1} }`（10 文字、`α = 2` の 5 文字を含むので **F20 を生成する**）
とし、§5.5 の機構が読める量を

    total phase P、phase ごとの到着数 A_q、非mover 別到着数 N[k,q]（k は ε=0 の 5 文字）、
    certify された pair cut（10 文字では空）、文字数 |w|_g mod 5、最初の文字、最後の文字

および**その反転語上の同じ量**（高さ 1 は反転で閉じるので反転は無料）とする。このとき:

> **主張.** この特徴族は μ を分離しない。すなわち特徴がすべて一致するが群元が異なる語の対が存在する。
> 最小の witness は長さ 4 であり、次で与えられる。

    k  = g(ε=0, β=0),  u₀ = g(ε=1, β=0),  u₁ = g(ε=1, β=1)
    w0 = k u₀ u₁ k     μ(w0) = (4, 1)
    w1 = k u₁ u₀ k     μ(w1) = (4, 2)

### 証明

1. **ε 列が同一**: 両語とも (0,1,1,0)。したがって **phase orbit が同一** (0,1,2,2)。
2. よって phase ごとの到着数 A_q が一致し、total phase P = 2 も一致する。
3. k の出現位置（1 番目と 4 番目）と、そこでの phase（0 と 2）が両語で同一なので、
   非mover 別到着数 N[k,q] が一致する。他の非mover は出現しないので 0 で一致。
4. **certify されたペアパターンは存在しない**（§1 の表）。したがってペア由来の特徴は無い。
5. 文字の多重集合が同一（隣接 2 文字の入れ替えのみ）なので |w|_g mod 5 が一致。
   最初と最後の文字はともに k で一致。
6. 反転語 `k u₁ u₀ k` と `k u₀ u₁ k` は互いに w1, w0 であり、1–5 が同じ形で成り立つ。
7. 一方 β は分離する。β(w) = Σ_i β_{g_i} 2^{E_i}（E_i は後続の ε 和）より

       β(w0) = β_{u₀}·2^{ε_{u₁}+ε_k} + β_{u₁}·2^{ε_k} = 2β_{u₀} + β_{u₁} = 1
       β(w1) = 2β_{u₁} + β_{u₀} = 2

   β_{u₀} ≠ β_{u₁} なので 2β_{u₀}+β_{u₁} ≠ 2β_{u₁}+β_{u₀}（mod 5）。∎

### 最小性

長さ ≤ 3 では衝突が無い（全 1,765 語の総当たり）。長さ 2 の `u₀u₁` / `u₁u₀` は β が違うが
**最後の文字**が違うので分離される。長さ 3 の `u₀u₁k` / `u₁u₀k` は**最初の文字**で分離される。
入れ替えを内部に埋めるには前後に非mover が必要で、長さ 4 が最小である。

## 3. 15 文字でも同じ witness が効く（ルート (ii) の反証）

witness は **ε = 3 の文字を一つも含まない**。15 文字で追加的に certify されるペアは (1,3) と (3,1)
だけなので、witness 上では一度も発火しない。したがって特徴ベクトルは 15 文字でも一致し、
`N-F20-001` のルート (ii) は**閉じない**。機械検証済み（§4 の最終行）。

さらに、certify されていない `Σeps = 0` パターン 555 個を無償で与えても衝突は消えない。
機構に有利に盛った上での失敗である。

**射程**: 示したのは「**この 555 個を足しても消えない**」ことのみである。特徴族を別の方向へ
広げれば消える可能性は排除していないし、「絞りすぎの人工物ではない」という一般の結論は
ここからは出ない。判定器そのものの健全性も別問題で、§3.5 が担当する。

## 3.5 判定器の positive control

同じ特徴族を 2 生成元アルファベット（`RESULTS.md` §5.11）に適用すると、長さ ≤ 12 の
全 8,191 語で衝突ゼロ、すなわち `mu` は特徴の関数になる。非 mover の single cut が `N_q` を
直接与えるためで、これが `F20-STD-01` の機構そのものである。**この対照が示すのは、判定器が
常に FAIL を返すわけではないという一点のみ**である。

特徴族が十分に広いかどうかは、**この note のどの実験も答えていない**。§3 の 555 パターンは
その 555 個を足しても消えないことを示すだけで、別の方向への拡張には触れない。未解決のまま
であることを、ここに明示しておく。

## 4. 何が本質か

- §5.12 で局在させた ε = 2 の障害は「base cut 自体が aperiodic でない」という **certification layer** の問題。
- 今回の障害は certification layer とは別で、**「同じ ε を持つ相異なる 2 文字の順序を決める手段が無い」**という
  **表現力**の問題である。mover の β 寄与を分離するにはペア情報が必要だが、それが certify できない。
- 2 生成元版（`F20-STD-01`）が通ったのは、**phase を動かす文字が 1 個・β を出す文字が 1 個**で
  順序問題が生じないからである。非mover single cut が `N_q` を直接与えて β が決まる。
  positive control（§6）でこれを再現し、判定器が空虚でないことを確認した。
- 一般化: witness の構成は「ε = 0 の文字 1 個＋ε が等しく β が異なる mover 2 個」しか使わない。
  この 3 文字を含み、かつ witness 中に現れるパターン ((0,ε), (ε,ε), (ε,0)) がいずれも
  certify されないアルファベットでは、同じ議論が通る。F20 では `α = 2` の 5 文字が β = 0..4 を
  すべて実現するので、**`FULL-ALPH-RED-01` が要求する全 20 元では必ずこの状況になる**。

## 5. 主張していないこと

- **高さが 2 であるとは主張しない。** これは既知の 1 機構（§5.5 の pattern-conditioned cut）の
  表現力の限界であって、下界ではない（README 研究ルール 1）。
- `F20-STD-01`（2 生成元、§5.11）は**影響を受けない**。
- `F20-FULL-OBS-01`（§5.12）の内容も**訂正ではない**。あちらの ε = 2 局在は base cut の
  aperiodicity についての正しい観察であり、本ノートはそれとは別の層の障害を加える。
  ただし §5.12 の「次の一手 (ii) は有望」という評価だけは本ノートで**反証**される。

## 6. 次の一手（`PROOF_OBLIGATIONS.md` N-F20-001 を差し替え）

ルート (i)（`Z/4 ⊃ {0,2} ⊃ 0` フィルトレーション）も、phase 群の分解であって
**同じ ε の文字の順序問題には触れない**ので、単独では今回の障害を回避できない。
残る方向は機構そのものの取り替えである:

1. ~~**有限符号（§5.9 の cascade code）に基づく分解へ乗り換える。** phase arrival で cut するのを
   やめ、語を有限符号 C 上のブロックに分解し、(a) ブロック言語が star-free、(b) β が
   ブロックごとの決定可能量の和、を満たす C を探す。§5.9 の Weis L2 族で実際に機能した
   アーキテクチャで、順序情報をブロック内部に閉じ込められる可能性がある。~~
   **BLOCKED（2026-07-25、`F20-BLOCK-OBS-01`、`notes/f20_block_decomposition.md`）。**
   全要素アルファベットには単位元が文字として入っているため、有界遅延の**有限**符号は
   `mu(X) = G` を強制される（遅延定理、3 行の証明）。トークン語は再び群元を文字とする語で
   座標公式も同じなので、ブロック分解は**自分自身への還元**でしかなく、`eps = 2` の障害が
   そのままトークンレベルに再現する（291 候補すべて失敗）。有限性を諦めても、唯一の正準な
   phase 中立符号（最初の帰還語 `R`、`T = R*`）は無限であり、しかもその DFA は §5.5 の
   base cut そのものなので star-free でない。残るのは「star-free な**無限**符号」だけ。
2. **反転以外の閉性を使う。** 高さ 1 は反転・補・共通部分で閉じる。現在の機構は反転しか
   使っていない。文字ごとの逆像（inverse *alphabetic* morphism は高さを保つ）で
   アルファベットを縮小し、複数の縮小版の共通部分として復元する方向。
   注意: **非アルファベット的な逆準同型は高さを保たない**（PST 1992 項目 7）。
3. **下界側に回る。** 「F20 の全アルファベット word problem は高さ ≥ 2」を目標にする。
   これは generalized star-height の下界であり、既知の技術では極めて困難（高さ 2 の下界は
   1 例も知られていない）。安易に着手しない。
